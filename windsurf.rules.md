# Правила AI-правок для репозитория

## 1) Секреты и чувствительные данные

- AI **нельзя редактировать** файлы, содержащие секреты или потенциально содержащие секреты (например: `config.ini`, `.env`).
- AI может **только читать** такие файлы **для понимания структуры** (ключи/секции/формат), без копирования/логирования содержимого секретов.
- AI **нельзя предлагать реальные SMTP-пароли**.

## 2) Что считать конфигами проекта

- Конфигами проекта считаются:
  - `config.example.ini`
  - `config.ini`

## 3) Что считать рабочими данными

- Рабочими данными считаются любые файлы и каталоги в:
  - `data/*`
  - `output/*`
  - `logs/*`

AI не должен изменять/перезаписывать рабочие данные без явного запроса.

## 4) Где находится кодовая логика проекта

- Ключевая кодовая логика проекта находится в:
  - `forecast_*.py`
  - `utils/`
  - `scripts/`

Изменения логики следует выполнять преимущественно в этих местах.

## 5) Любые изменения секретов — только через пользователя

- Любые изменения секретов (значения токенов, паролей, ключей, приватных URL и т.п.) выполняются **только через пользователя**.
- AI **не предлагает реальные значения** секретов и **не подставляет** их в код/конфиги.
- Если для работы требуются значения секретов, AI:
  - описывает, **какие именно** значения нужны (названия ключей/переменных),
  - просит пользователя предоставить их безопасным способом,
  - или просит пользователя внести их вручную.
