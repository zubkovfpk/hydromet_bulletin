# Сбор метеоданных GFS (NOAA NOMADS)

## Назначение процесса

Ручная подготовка входных метеоданных GFS для скрипта через запуск парсера, который формирует HTTP-запросы к NOAA NOMADS, получает целевые переменные прогноза и проверяет полноту данных по срокам.

## Источники данных и доступа

### 1) NOAA NOMADS (NCEP / NOAA)

- **Тип источника:** веб-сервис/портал данных.
- **URL:** `https://nomads.ncep.noaa.gov/cgi-bin/filter_gfs_0p25_1hr.pl`
- **Метод доступа:** парсер (скрипт), формирующий HTTP-запросы к CGI-фильтру для выборочной загрузки переменных.
- **Форматы данных:** `GRIB2 (.grb2)` и `NetCDF (.nc)`.
- **Периодичность обновления у источника:** 4 раза в сутки.
- **Ручные шаги:**
  - запустить парсер по регламенту;
  - проверить, что парсер обращается к актуальному URL фильтра;
  - подтвердить успешную выгрузку файлов в рабочую папку.

### 2) Локальный файл конфигурации парсера (config)

- **Тип источника:** локальный конфигурационный файл.
- **Описание:** задает список переменных (например, `TMP`, `UGRD/VGRD`, `PRMSL`) и временные шаги прогноза (`forecast hours`).
- **Формат данных:** текстовая конфигурация (параметры скрипта).
- **Периодичность обновления:** по мере изменения задач/набора параметров.
- **Ручные шаги:**
  - задать/проверить список переменных;
  - задать/проверить горизонт и шаг прогноза (например, 0-72 часа с шагом 1 час);
  - проверить корректность синтаксиса конфигурации.

### 3) Рабочая папка данных

- **Тип источника/приемника:** локальная директория для результатов парсера.
- **Форматы данных:** `GRIB2 (.grb2)` как исходные данные и `NetCDF (.nc)` как конвертированная/параллельная версия для аналитики.
- **Периодичность обновления:** по расписанию запусков парсера (в текущей задаче 2 раза в сутки).
- **Ручные шаги:**
  - проверить наличие обоих форматов после скачивания;
  - при отсутствии одного из форматов запустить конвертацию или повторный запрос;
  - проверить полноту полученных прогнозных сроков.

## Регламент и параметры выполнения

- Периодичность обновления GFS: 4 раза в сутки.
- Периодичность скачивания для текущей задачи: 2 раза в сутки (перед утренним и вечерним бюллетенями).
- Выбор модельного цикла: `00z`, `06z`, `12z`, `18z`.
- Принцип загрузки: скачиваются только нужные переменные через CGI-фильтр, без загрузки полного массива данных.

## Пошаговая логика бизнес-процесса

1. Запустить парсер согласно расписанию скачивания.
2. Прочитать параметры из локального файла `config`.
3. Извлечь список переменных и горизонт прогноза.
4. Вычислить текущую дату и актуальный цикл модели (`00z/06z/12z/18z`).
5. Сформировать URL запроса с параметрами каталога, переменных и сроков прогноза.
6. Отправить HTTP-запрос к NOAA NOMADS CGI-фильтру.
7. Сохранить полученные данные в рабочую папку.
8. Проверить наличие форматов `GRIB2` и `NetCDF`.
   - Если один формат отсутствует, выполнить конвертацию или повторный запрос.
9. Проверить, что все прогнозные сроки из конфигурации присутствуют в полученных данных.

## Критерии успешной загрузки

- Парсер успешно сформировал и отправил запрос с параметрами из `config`.
- В рабочей папке сохранены файлы в требуемых форматах: `.grb2` и `.nc`.
- Данные покрывают необходимый временной горизонт прогноза (например, 24/48/72 часа).
- Все запрошенные сроки прогноза получены.

## Типовые точки отказа

- **Ошибки в config:** некорректный синтаксис или неверные параметры приводят к пустому/некорректному запросу.
- **Изменение структуры URL NOAA:** формат путей/дат может измениться, из-за чего шаблон запроса становится невалидным.
- **Ограничения/лимиты NOAA:** при слишком частых запросах возможно временное ограничение доступа по IP.
- **Неполная готовность прогноза:** на момент запуска часть прогнозных часов еще не опубликована.
- **Неполный набор форматов:** отсутствует один из форматов (`GRIB2` или `NetCDF`) и требуется повторная обработка.

## Конфигурационные параметры для дальнейшего редактирования `config.example.ini` и `.env.example`

Ниже приведены параметры, которые целесообразно вынести в конфигурацию без изменения текущей логики процесса.

### Параметры источника NOAA

- `GFS_BASE_URL` - базовый URL CGI-фильтра NOAA NOMADS.
- `GFS_MODEL_PATH_TEMPLATE` - шаблон каталога модели с датой/циклом (например, `gfs.{yyyymmdd}/{cycle}`).
- `GFS_CYCLES` - список поддерживаемых циклов (`00z,06z,12z,18z`).
- `GFS_UPDATE_FREQUENCY_PER_DAY` - частота обновления данных у источника (4).

### Параметры скачивания

- `DOWNLOAD_FREQUENCY_PER_DAY` - частота запусков скачивания (в текущем сценарии 2).
- `DOWNLOAD_SCHEDULE_CRON` - расписание запуска парсера.
- `HTTP_TIMEOUT_SECONDS` - таймаут HTTP-запроса.
- `HTTP_RETRY_COUNT` - число повторных попыток при сетевой ошибке.
- `HTTP_RETRY_DELAY_SECONDS` - задержка между повторными попытками.

### Параметры прогноза и выборки

- `FORECAST_HOURS_START` - начальный срок прогноза (например, 0).
- `FORECAST_HOURS_END` - конечный срок прогноза (например, 72).
- `FORECAST_HOURS_STEP` - шаг прогноза (например, 1).
- `GFS_VARIABLES` - список метеопеременных (`TMP,UGRD,VGRD,PRMSL,...`).
- `GFS_LEVELS` - список уровней (высоты/давления), передаваемых в фильтр.

### Параметры форматов и валидации

- `REQUIRED_FORMATS` - обязательные форматы результата (`grb2,nc`).
- `ENABLE_CONVERSION_TO_NETCDF` - признак конвертации в `NetCDF`, если `nc` отсутствует.
- `CHECK_FORECAST_COMPLETENESS` - проверка полноты сроков прогноза.
- `MIN_EXPECTED_FILES` - минимально ожидаемое количество файлов в цикле.

### Параметры хранения и логирования

- `WORK_DIR` - рабочая директория скачивания.
- `OUTPUT_DIR` - директория финальных файлов для аналитики/дальнейших шагов.
- `LOG_LEVEL` - уровень логирования (`INFO`, `WARNING`, `ERROR`).
- `ALERT_CHANNEL` - канал уведомлений о сбоях (email/messenger/др.).

### Чувствительные параметры (только для `.env.example`)

- `NOAA_API_TOKEN` - токен (если используется прокси/шлюз с авторизацией).
- `NOAA_CLIENT_ID` - идентификатор клиента (если требуется внешним шлюзом).
- `NOAA_CLIENT_SECRET` - секрет клиента.
- `PROXY_USERNAME` / `PROXY_PASSWORD` - учетные данные прокси (если используется).
