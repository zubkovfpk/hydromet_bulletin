# Сбор данных о волнении океана (Copernicus Marine)

## Назначение процесса

Ручная подготовка входных данных для скрипта прогноза волнения океана на основе данных Copernicus Marine Service (CMEMS) с последующей проверкой, обработкой и размещением в целевом хранилище.

## Источники данных и доступа

### 1) Copernicus Marine Service (CMEMS)

- **Тип источника:** веб-сервис/портал данных.
- **URL:** `https://data.marine.copernicus.eu`
- **Пакет данных:** `Global Ocean Waves Analysis and Forecast`
- **Dataset:** `cmems_mod_glo_wav_anfc_0.083deg_PT3H-i`
- **Пример URL каталога файлов:** `https://data.marine.copernicus.eu/product/GLOBAL_ANALYSISFORECAST_WAV_001_027/files?subdataset=cmems_mod_glo_wav_anfc_0.083deg_PT3H-i_202411`
- **Формат данных:** `NetCDF (.nc)`.
- **Периодичность обновления у источника:** 1 раз в сутки.
- **Периодичность ручного скачивания:** 1 раз в сутки.
- **Ручные шаги:**
  - выполнить авторизацию на портале;
  - перейти в актуальный каталог с динамическим путем формата `/yyyy/mm`;
  - выбрать файлы, соответствующие времени запуска скрипта;
  - скачать требуемое количество файлов.

### 2) Каталоги файлов CMEMS (динамическая структура)

- **Тип источника:** файловые каталоги на стороне CMEMS.
- **Описание пути:** структура обновляется по датам, например `.../2026/04/`, `.../2026/05/`, `.../2027/01/`.
- **Формат данных:** файлы `NetCDF (.nc)`.
- **Периодичность обновления:** ежемесячное появление новых каталогов + ежедневное обновление данных.
- **Ручные шаги:**
  - проверить доступность каталога текущего года/месяца;
  - при недоступности считать, что публикация данных задерживается;
  - при доступности выбрать самый актуальный файл(ы) по дате.

### 3) Локальная рабочая папка и целевое хранилище

- **Тип источника/приемника:** локальная рабочая директория и целевое хранилище системы.
- **Формат данных:** входные и обработанные `NetCDF (.nc)`.
- **Периодичность обновления:** синхронно с ежедневным циклом скачивания.
- **Ручные шаги:**
  - переместить скачанные файлы в рабочую папку с заменой одноименных предыдущих версий;
  - выполнить обрезку по целевой географической области;
  - разместить обработанные файлы в хранилище.

## Регламент подготовки данных

- Цикл выполнения: 1 раз в сутки.
- Целевой горизонт прогноза: 5 суток.
- Требуемое количество файлов: 10 файлов.
- Особенности выбора стартового файла:
  - при запуске, например, `03 апреля` в интервале `00:30-12:30` скачиваются 10 файлов, начиная с `mfwamglocep_2026040300_R20260403_00H`;
  - при запуске с `12:31 03 апреля` до `00:29 04 апреля` скачиваются 10 файлов, начиная с `mfwamglocep_2026040312_R20260403_00H` или `mfwamglocep_2026040312_R20260403_12H`.

## Пошаговая логика бизнес-процесса

1. Запустить скрипт.
2. Выполнить авторизацию на портале CMEMS.
   - Если авторизация неуспешна, сформировать сообщение о необходимости обновить токен/пароль.
   - Если авторизация успешна, перейти по динамическому URL каталога данных.
3. Проверить доступность пути по маске `/yyyy/mm`.
   - Если путь недоступен, считать, что данные еще не опубликованы.
   - Если путь доступен, найти наиболее актуальные по дате `.nc`-файлы с учетом времени запуска.
4. Скачать выбранные файлы.
   - Если загрузка прервалась, повторить попытку скачивания.
   - После успешного скачивания выполнить проверку целостности и даты.
5. Проверить целостность каждого файла.
   - Проверить соответствие структуры и типов данных эталонным файлам.
   - Проверить наличие необходимой области по заданным координатам.
   - Проверить наличие обязательных данных.
   - При ошибках/повреждении вернуться к шагу скачивания.
6. Обработать и разместить файл.
   - Обрезать файл до требуемой области по координатам.
   - Переместить обработанный файл в целевое хранилище.

## Критерии успешной загрузки

- Файл(ы) полностью загружены в целевое хранилище.
- Количество полученных файлов соответствует требуемому для заданного горизонта прогноза.
- Файлы содержат данные за актуальные сутки (по имени файла и/или метаданным).
- Файлы прошли проверки структуры, обязательных данных и географической области.

## Типовые точки отказа

- **Авторизация:** истек срок действия учетных данных (токен/пароль), требуется обновление.
- **Доступность данных:** каталог `/yyyy/mm` или нужные файлы еще не опубликованы провайдером.
- **Изменение URL/структуры портала:** смена версии продукта или пути к данным.
- **Изменение формата/структуры файла:** изменения в исходных данных у провайдера.
- **Сетевая нестабильность:** обрыв соединения при скачивании больших `.nc`-файлов.
- **Нарушение целостности файла:** повреждение, отсутствие нужных переменных/области/типов данных.

## Конфигурационные параметры для дальнейшего редактирования `config.example.ini` и `.env.example`

Ниже перечислены параметры, которые целесообразно вынести в конфигурацию без изменения текущей логики процесса.

### Параметры источника данных

- `CMEMS_BASE_URL` - базовый URL портала CMEMS (например, `https://data.marine.copernicus.eu`).
- `CMEMS_PRODUCT_PATH` - путь к продукту/разделу файлов.
- `CMEMS_DATASET_ID` - идентификатор dataset (`cmems_mod_glo_wav_anfc_0.083deg_PT3H-i`).
- `CMEMS_DYNAMIC_PATH_MASK` - маска каталога дат (`/yyyy/mm`).

### Параметры доступа и авторизации

- `CMEMS_USERNAME` / `CMEMS_PASSWORD` или `CMEMS_TOKEN` - учетные данные доступа.
- `AUTH_RETRY_ENABLED` - флаг повторной попытки при ошибке авторизации/загрузки.
- `AUTH_ERROR_NOTIFY` - признак отправки уведомления при ошибке авторизации.

### Параметры скачивания

- `DOWNLOAD_SCHEDULE_CRON` - расписание ежедневного запуска.
- `DOWNLOAD_FREQUENCY_PER_DAY` - количество циклов скачивания в сутки (по текущему регламенту: 1).
- `FORECAST_DAYS` - горизонт прогноза (по текущему регламенту: 5).
- `FILES_PER_CYCLE` - количество файлов на цикл (по текущему регламенту: 10).
- `DOWNLOAD_RETRY_COUNT` - количество повторов при обрыве скачивания.
- `DOWNLOAD_TIMEOUT_SECONDS` - таймаут загрузки файла.

### Параметры выбора файлов по времени запуска

- `RUN_WINDOW_1_START` / `RUN_WINDOW_1_END` - окно `00:30-12:30` для выбора серии с префиксом `...0300...`.
- `RUN_WINDOW_2_START` / `RUN_WINDOW_2_END` - окно `12:31-00:29` для выбора серии с префиксом `...0312...`.
- `FILE_NAME_PATTERNS` - допустимые шаблоны имен файлов для анализа/прогноза.

### Параметры валидации и обработки

- `REFERENCE_SCHEMA_PATH` - путь к эталонному описанию структуры/типов данных.
- `REQUIRED_VARIABLES` - список обязательных переменных в файле.
- `TARGET_BBOX` - координаты целевой области для проверки и обрезки.
- `VALIDATE_FILE_DATE` - проверка актуальности даты в имени/метаданных.
- `CROP_ENABLED` - признак обрезки данных по области.

### Параметры хранения и логирования

- `WORK_DIR` - рабочая папка для скачивания и временного хранения.
- `STORAGE_DIR` - целевое хранилище обработанных файлов.
- `REPLACE_SAME_NAME_FILES` - замена предыдущих версий с одинаковыми именами.
- `LOG_LEVEL` - уровень логирования процесса.
- `ALERT_CHANNEL` - канал уведомлений об ошибках (email/messenger/др.).
